# 技能文档的来源与许可

`src/agents/skills/` 下的这些 markdown 文档是给模型看的方法论说明，会被拼进
`src/agents/Prompts.py` 里对应的系统提示词。它们不是程序代码，但会随分发包一起
分发，所以来源和许可要写清楚。

## 一、`paper-deep-reading.md`

**来源**：`https://github.com/huangkiki/dailypaper-skills`（Apache License 2.0）。

具体取自下面这些文件里「怎么判断、怎么评价、怎么记」这一部分内容：

- `skills/daily-papers-review/SKILL.md` 的「铁律：基于事实评价」一节（四条「绝对禁止」
  与其对称的「你可以（且应该）做的」清单）
- `skills/paper-reader/SKILL.md` 的质量规则，以及
  `skills/paper-reader/references/quality-standards.md` 里关于表格与公式的提取要求，
  以及同一文件「公式质量检查」一节的差错类型（符号约定不一致、公式与文字描述不一致、
  漏掉关键算子等）
- `skills/paper-reader/assets/paper-note-template.md`（字段模板、关键公式的含义与符号
  说明、可复现性评估清单）与 `obsidian-templates/论文笔记模板.md`（「问题背景」三问）

**做了哪些改动**：

1. 改写成中文条目式表述，并压到很短的篇幅（每个小节都有字数上限，见下）。
2. **只保留方法，去掉全部执行步骤**——原文里的 Obsidian 笔记保存、Zotero 集成、
   `[[概念]]` 双链、图片下载与 URL 去重、概念库维护、git 提交等，在本项目里没有
   对应的执行环境，全部删除。
3. **去掉了原文的「毒舌」语气与 emoji 判决标签**：本项目产出的是给用户存档和追问
   用的评分报告，语气要求会污染评分理由字段。
4. 「零遗漏所有 Figure / 公式 / Table」这条**没有采用**：精读报告的结构是固定的，
   字段只有纯文本，没有专门承载图像或表格的位置（公式可以夹在文本字段里，见下文
   「公式写法」一节），所以图像与表格「全部出现」这件事没有地方落。
   原文中关于「装不下时先保什么」的取舍思路被保留下来，改写成「逐段阅读取舍」——
   那一节讲的正是分段阅读时的优先级，与报告字段无关，因此不受此限制影响。
5. 把原文中面向「笔记」的说法统一改成「输入材料」，因为同一份内容要同时用于
   「有分段笔记的汇总」和「只有标题摘要的降级」两条路径。
6. 「公式写法」分成了排布与内容两层。排布层（`$...$` / `$$...$$`）是本项目自己的
   要求，因为前端按这个渲染公式；内容层的全部条目（符号沿用原文、算子写全、文字描述
   的性质要体现在公式里、公式残缺时如实说明，以及第 8 条补的两条差错检查）都来自
   上面提到的 `quality-standards.md`。
7. 「逐段阅读取舍」里「超出部分从末尾截掉、最该留的写在前面」这几句**不是上游内容**，
   是本项目按 `deepReadAgent.py` 的实际实现补的：分段笔记在模型输出之后由程序按字数
   从尾部硬切到 500 字，模型看不到截断位置，所以必须要求它把重要的内容排在前面。
   原有的「先保方法与实验数据」是同一个意思的上游说法，一并保留。
8. 「公式写法」的「内容」部分在原有四条之外补了两条差错检查：同一个符号既作求和变量又
   作自由变量时要照抄原文并点出来、上下限与上下标要逐个核对材料。两条都来自上游
   `quality-standards.md` 的「公式质量检查」一节（那一节以 $v(s_\tau)=\sum_\tau r_\tau$
   为例，指出 $\tau$ 同时充当求和变量与自由变量，并要求逐字核对求和范围与上下标），
   这里只是把措辞压短，没有添油加醋。
9. 「字段句式模板」一节的句式由本项目和上游共同构成。**改写自上游的部分**：研究问题那句
   （「针对{什么不足}，提出{什么}」）取自 `obsidian-templates/论文笔记模板.md` 的
   「问题背景」三问（要解决的问题 / 现有方法的局限 / 本文的动机），只留了能落进一句话的
   那半句；方法类的「输入 → 骨干 → 核心模块 → 输出」取自 `assets/paper-note-template.md`
   的「模型架构」小节；数据集那条的「规模 + 特点」取自同文件的「实验 / 数据集」表头。
   **本项目自拟的部分**：结果类句式、实验设置排序、数字照抄、总结那句——报告字段就那么
   几个，逐条写清「在什么条件下、对谁、是什么、数值多少」，用户不回原文就能读懂。
   字段名与取值范围一律以 `Prompts.py` 为准，这一节只管句子怎么写。
10. 「公式写法」的内容层新增一条：公式要自带说明（点明它是什么、一句说它算出来的是什么、
   符号逐个说明）。改写自 `skills/paper-reader/SKILL.md` 的「公式完整性」与
   `assets/paper-note-template.md` 的「关键公式」小节（上游要求名称 + LaTeX + 含义 +
   符号说明四件齐备）。有一处刻意改了口径：上游要求符号说明必须齐全，本项目改成
   「材料没解释的就跳过，不要猜」——报告字段里的公式是从材料抄来的，材料本身没给
   符号含义时硬猜会违反「不得编造」。
11. 「评价纪律」新增两处。一是严谨性要把可复现性算进去（代码、模型权重、训练细节、
   数据获取缺哪项就低在哪），改写自 `assets/paper-note-template.md` 的「可复现性评估」
   清单，并加了「材料没提就写『输入材料未提及』、不要断言『没开源』」的护栏以对齐本项目的
   四条硬禁止。二是「可以且应该做的」那句扩写了实验覆盖面与「计算成本、数据需求、
   工程复杂度」两个观察角度，取自 `skills/daily-papers-review/SKILL.md` 的「你可以（且
   应该）做的」清单。上游同一清单里「质疑标题是否夸大、贡献是否只是把已有方法的零件
   换了换」**没有采用**——它与本项目「不得断言是已有工作的翻版换皮」这条硬禁止相抵。

**依据**：Apache License 2.0 第 4 条要求随分发附上许可证副本。副本见同目录下的
`LICENSE-APACHE-2.0.txt`。

## 二、`literature-review.md`

**来源**：整理自一份本地收集的、标题为「文献综述写作」的中文材料（文件名为
`SKILL.md`）。**该材料没有附带任何许可证，正文里也没有版权声明**，无法确认其来源
与授权，因此**没有复制它的任何文字**。

文档里实际使用的内容——按时间 / 主题 / 方法流派 / 理论四种组织逻辑，以及
「主题句 → 文献支持 → 综合分析 → 批判性评价 → 过渡」这段段落骨架——是学术写作里
通行的通用方法，任何一本写作指南都会讲到，不构成对某一份文档的复制。

**没有采用的部分**：该材料里关于文献检索策略、常用数据库清单、文献管理软件
（Zotero / EndNote / Mendeley）的内容，以及引言与结论的写作模板——前两类在本项目
里由检索工具自动完成，第三类与综述流水线「只产出正文章节」的设计相冲突。

**本次补充的判据**（供模型自检用；每条注明是本项目自拟，还是改写自上游技能库
`dailypaper-skills`，Apache License 2.0）：

- 「正文写作原则与段落骨架」里判断逐篇罗列的判据（同一段里连续两句以上以论文名或
  `[paperId]` 作主语），以及素材只够一篇、证据为空时的降级写法。
- 「正文审查清单」里「有没有用形容词代替证据」这一条。加它是因为正文审查节点只拿得到
  小节任务和正文草稿，看不到证据，原先那条「有没有批判性评价」在审查时根本无从判断。
  批判性评估的要求随之挪进了「正文写作原则与段落骨架」，写手拿得到证据，那里才做得成。
- 「章节组织结构」里的两条自检办法（把标题连起来能不能一句话说出组织线索；一半以上的
  章按同一逻辑拆）。
- 「公式与表格写法」这一节，以及「正文审查清单」里新加的「公式和表格能不能原样用」
  一条。公式的排布写法（`$...$` / `$$...$$`）与精读报告那边保持一致，因为终稿是要下载
  下来看的 Markdown。表格的规矩也写在这里：只在三篇以上文献有可对齐数值时才用，数值
  必须来自检索到的原文（不能拿结构化摘要里被截短的数字拼表），凑不齐就把数值写进段落。
  **上游 `quality-standards.md` 的「ALL Tables」讲的是「提取时一张表都不能漏」，不是
  「输出时怎么写表」，所以这里一个字都没采用**，全部是本项目自拟的呈现要求。
- 「章节组织结构」里「拆章要按『解决什么问题』划界，不要一章按技术拆、一章按问题拆」
  这条，改写自上游 `skills/paper-reader/references/zotero-guide.md` 的「按主要贡献分类，
  而非使用的技术」——上游用它给 Zotero 条目分类，这里挪来管拆章。
- 「正文写作原则与段落骨架」里「不要自造一版简化结论顶上去，也不要默不作声地跳过」
  这句，改写自上游 `skills/daily-papers-notes/SKILL.md` 的「铁律」与「绝对禁止自己手写
  简化版笔记」。本项目只保留「不缩水、不自造简化版」这一半，去掉了上游针对 agent
  长流程的耗时与阶段提交纪律——那些在本项目里没有对应环节。

## 三、篇幅上限（维护时注意）

这些文档会被追加到已有的系统提示词末尾，直接增加每一次模型调用的输入长度。所以
每个小节都有硬性上限，改文档时不要超：

| 文档 / 小节 | 上限 | 现有 | 说明 |
|---|---|---|---|
| `literature-review.md` / 章节组织结构 | 380 汉字 | 360 | 注入大纲阶段的提示词 |
| `literature-review.md` / 正文写作原则与段落骨架 | 455 汉字 | 435 | 注入逐节写作的提示词 |
| `literature-review.md` / 正文审查清单 | 260 汉字 | 193 | 注入正文审查的提示词 |
| `literature-review.md` / 公式与表格写法 | 300 汉字 | 245 | 注入正文写作的提示词。公式排布与精读报告保持一致；表格部分是本项目自拟的呈现要求（上游的「ALL Tables」讲的是提取时一张不漏，不是输出怎么写，故未采用） |
| `paper-deep-reading.md` / 逐段阅读取舍 | 210 汉字 | 198 | 注入分段阅读的提示词，**按块调用多次，乘数最大**，所以额度卡得最紧 |
| `paper-deep-reading.md` / 公式写法 | 390 汉字 | 372 | 注入汇总与降级两条路径。排布那段不是来自上游素材，是本项目加的：前端的精读报告按 `$...$` 渲染公式（见 `front/src/components/chat/MathText.vue`），模型不按这个写法输出就渲染不出来 |
| `paper-deep-reading.md` / 评价纪律 | 650 汉字 | 622 | 注入汇总与降级两条路径的提示词 |
| `paper-deep-reading.md` / 字段句式模板 | 335 汉字 | 317 | 注入汇总与降级两条路径的提示词 |

`paper-deep-reading.md` 的后三节（评价纪律 + 公式写法 + 字段句式模板）在 `Prompts.py` 里
会被拼成同一个字符串（`_DEEP_READ_REPORT_SECTIONS`），一起注入汇总与摘要降级两条路径，
所以要**合起来看**：目前这三节合计 1311 汉字，再加内容前先想想这两条路径各会多付多少
输入长度。注意其中「实验覆盖面」「可复现性」这两段对只有标题摘要的降级路径基本用不上，
是那一条路径上白付的成本。

「现有」一列是 2026-09-13 这一版的实际汉字数，改完顺手更新它，便于下一次修改时知道还剩多少余量。

**这些上限是人工约定，程序并不检查**（程序只检查下面那条 `JSON`）。超了不会报错，只会
静默拉长每一次模型调用的输入，所以只能靠改的人自己守。

另外，「逐段阅读取舍」这一节**不得出现 `JSON` 字样**：分段阅读输出的是纯文本笔记，
和汇总阶段的 JSON 输出要能区分开。程序启动时会检查这一条，违反了会直接报错。
