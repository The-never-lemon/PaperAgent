# 综述撰写方法论

这份文档写的是「综述正文该怎么组织、怎么写」，供综述链路的**大纲、写作、审查**
三个阶段按需取用。

它只管方法，不管输出格式——输出哪些字段、什么形状，由 `Prompts.py` 里的提示词
规定。个别地方会用括号点一下字段名或标记的写法，那只是为了说得清楚，字段名一律
以 `Prompts.py` 为准。

每个二级标题就是一个小节，`Prompts.py` 按小节名取用，所以**不要改标题文字**，
改了会在程序启动时直接报错（这是故意的，避免改了名字却没人发现）。

## 章节组织结构

正文按下面四种逻辑之一来组织。先判断手头材料更像哪一种，再拆章节：

- **按时间**：方法或关注点随年份明显演变时用。章节名体现阶段，如「早期基于规则的方法」「深度模型时期」。
- **按主题**：材料能自然分成几个并列关注点时用。章节名就是各关注点本身，最常用。
- **按方法流派**：同一问题下多种技术路线并存、彼此可比较时用。章节名体现路线，如「基于检索的方法」「基于微调的方法」。
- **按理论**：材料围绕几个理论或模型展开时用。按理论逐一展开，末尾单列一节讲理论之间如何整合。

组织方式要**落在章节标题上**，不能只写在 description 里。自检办法：把所有标题连起来
看一遍，能不能一句话说出这份综述按哪条线索组织，说不出就是没做到。

允许混用，但要有一条主线索：**一半以上的章按同一种逻辑拆**，剩下的章才可以用别的
逻辑做次级安排。不要四种逻辑各取一点，拼成大杂烩。

## 正文写作原则与段落骨架

一节正文一次写完（通常 600~800 字），由三到四个段落推进，每段按这个骨架写：

主题句点明观点 → 两三篇文献作证据（句末标 `[paperId]`）→ 综合出结论 → 指出局限或
反例 → 过渡到下一段。

四条原则：

1. **综合，不罗列**：多篇论文放在一起比较，写「这些研究共同表明……」「与之相反，另一组工作发现……」，不写「论文 A 做了……论文 B 做了……」。自检办法：同一段里连续两句以上以论文名或 `[paperId]` 作主语，就是罗列。
2. **解释，不复述**：给出判断和因果，用「这表明……」「这意味着……」把证据和观点连起来。
3. **批判性评估**：指出方法的局限、适用边界、评估范围是否充分。局限必须来自证据，不要为了凑出批判而写「仍需进一步研究」这类套话；证据里确实没有局限时，就写方法本身的适用条件。
4. **有过渡**：段与段之间用「然而」「相比之下」「在此基础上」连接。

素材只够一篇文献时，不要硬凑比较：写成「目前只见到一项工作采用……，它把……作为
前提」，并放进所属方法谱系里交代位置。本节证据为空时，用已调用工具拿到的资料来写；
仍然写不出的部分直接写明「现有证据未覆盖」，不要用「普遍认为」「均」「从未」这类
没有文献支撑的说法顶上去。

## 正文审查清单

在原有检查之外，额外核对两条。审查时只拿得到小节任务和正文草稿，所以下面两条都能
只凭草稿本身判断：

- **有没有退化成逐篇罗列**：同一段里连续两句以上以论文名或 `[paperId]` 作主语，就是没达标。要指出是哪几句，并说明该合并成哪一句跨文献比较。
- **有没有用形容词代替证据**：出现「效果更好」「性能明显提升」这类结论，却没有给出数据集、指标或比较对象的位置，要指出来。
