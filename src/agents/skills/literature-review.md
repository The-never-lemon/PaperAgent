# 综述撰写方法论

这份文档写的是「综述正文该怎么组织、怎么写」，供综述链路的**大纲、写作、审查**
三个阶段按需取用。

它只管方法，不管输出格式——输出哪些字段、什么形状，由 `Prompts.py` 里的提示词
规定；这里出现的任何规则都不涉及字段名。

每个二级标题就是一个小节，`Prompts.py` 按小节名取用，所以**不要改标题文字**，
改了会在程序启动时直接报错（这是故意的，避免改了名字却没人发现）。

## 章节组织结构

正文按下面四种逻辑之一来组织。先判断手头材料更像哪一种，再拆章节：

- **按时间**：方法或关注点随年份明显演变时用。章节名体现阶段，如「早期基于规则的方法」「深度模型时期」。
- **按主题**：材料能自然分成几个并列关注点时用。章节名就是各关注点本身，最常用。
- **按方法流派**：同一问题下多种技术路线并存、彼此可比较时用。章节名体现路线，如「基于检索的方法」「基于微调的方法」。
- **按理论**：材料围绕几个理论或模型展开时用。按理论逐一展开，末尾单列一节讲理论之间如何整合。

选定的组织方式要**体现在章节标题本身**，不能只写在 description 里——读者看目录就
该知道这份综述是按什么线索组织的。允许混用，但要有主次，不要四种逻辑各取一点拼成
大杂烩。

## 正文写作原则与段落骨架

四条原则：

1. **综合，不罗列**：多篇论文放在一起比较，不一篇一段依次介绍。写「这些研究共同表明……」「与之相反，另一组工作发现……」，不写「论文 A 做了……论文 B 做了……」。
2. **解释，不复述**：给出判断和因果，用「这表明……」「这意味着……」把证据和观点连起来。
3. **批判性评估**：指出方法的局限、适用边界、评估范围是否充分。只夸不批的段落等于没有分析。
4. **有过渡**：段与段之间用「然而」「相比之下」「在此基础上」连接，让读者知道下一段为什么接在这里。

段落骨架：主题句点明观点 → 两三篇文献作证据（句末标 `[paperId]`）→ 综合出结论 →
指出局限或反例 → 过渡到下一段。

不得用「普遍认为」「均」「从未」「显著优于」代替证据；没有具体文献支撑的判断不要
写成结论。

## 正文审查清单

在原有检查之外，额外核对两条：

- **是否退化成逐篇罗列**：若一节读起来是「P1 做了 A。P2 做了 B。」依次介绍，就是没达标，要指出哪几句是罗列、该改成跨文献比较。
- **有没有批判性评价**：若全节只有正面陈述、没有任何局限或边界讨论，要指出来。
