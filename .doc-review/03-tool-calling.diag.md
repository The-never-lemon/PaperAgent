## 一句话总评

代码事实基本可靠（11 处行号围栏全部对得上，常量与流程也几乎逐条正确），问题出在**可读性和上手顺序**上：「设计理念」11 条决策被整段前置到正文之前，新人在还不知道 `ToolRegistry`、handler、工具卡是什么的时候，要先连读 90 多行「为什么不那样写」；正文里又夹了 3 处会被追问戳穿的表述（`ToolCallRequest` 少写一个字段、「源码里是 arXiv 和 OpenAlex」、`get_chunk_by_embed` 那段「以后接上向量库」撞上项目红线）。

## 一、必须保留的东西

改写时一条都不许丢：

- **开篇一句话定位**（`L3`）：「模型不直接干活。它只输出「要调哪个工具、参数是什么」，真正动手的是代码。」一句话说清本层职责，是全文最好的开场。
- **§0 的 mermaid 全局图**（`L17`–`L30`）+ **`L32` 的「四件事」讲法**（补齐字段、落库、并行执行、回灌结果）。一张图串完「模型输出 → 补齐 → 落库 → 并行执行 → 统一出口 → 回填 → 下一轮」。
- **§0 的「左中右」导航**（`L34`）：「左边是工具长什么样，中段是谁来执行，右边是不同协议的差异怎么对齐」。读者全程知道自己站在哪。
- **「设计理念」11 条决策的三句话固定结构**（要解决的问题 / 考虑过的做法 / 最终选择+代价）。格式统一、条目独立，改写时不许把结构改成散文。
- **决策 8 的完整推理链**（`L106`–`L108`）：`isinstance(exc, TimeoutError)` 为什么是错的、`ReadTimeout` 的真实继承链、以及「重试逻辑等于没写」的后果。全篇最有价值的一段踩坑科普，一个字都别删。
- **决策 4 的 `no_url` 讲法**（`L70`–`L74`）：用「付费墙论文不该出红卡」讲清「优雅降级 ≠ 失败」，并把「**不要**把它列进表」写成显式警告。
- **决策 10 的取景**（`L120`）：用「三张卡片的内容会互相串」这个具体现象讲 `ContextVar`，比抽象解释 task-local 好得多。
- **§2 的 11 个工具表格**（`L208`–`L220`）。「工具 | 类型 | 做什么」三列，一屏看完主 Agent 的能力边界。
- **§2 参数协议的冻结约定**（`L229`–`L238`）+ 逐字引用的模块说明围栏。这是改动前必读的硬约束。
- **§3 开头那段纯文本调用链**（`L248`–`L256`）。从 `chat_stream` 到「回填角色 role=tool + 落库」，一行一步，比任何文字都直观。
- **§3.2 的失败表源码引用**（`L299`–`L312`）+ 紧随其后的判定条件一句话（`L314`）。把「三种失败形态」和「哪些算失败」一次说清。
- **§3.3 的统一出口**（`L318`–`L337`）：`render_tool_result` 做唯一出口的**理由**（类型不支持会报错 + 几百 KB 会占满上下文）和**代价**都写了，这种「讲清为什么」的段落要留。
- **§4 的七步 mermaid 图 + 逐条展开**（`L355`–`L373`）。每步都对应一个真实问题（例如第 2 步的「假描述」、第 6 步的「有链接却下载失败」），这是全篇第二厚的一段。
- **§7 的 Anthropic 三条约束及其兜底**（`L465`–`L494`），特别是 `INTERRUPTED_TOOL_RESULT` 那段「刻意写成『这次没执行』，不写成一条错误」的理由。这是新人都该知道的协议坑。
- **§8 的 `yield_to_event_loop()` 解释**（`L511`）：`asyncio.sleep(0)` 为什么必须有、不让出会怎样。三段话讲透一个隐性时序依赖。
- **逐字源码围栏 + `起始行:结束行:文件路径` 的约定**（`L138` 有说明）。
- **小结的 5 条**（`L521`–`L525`）与「读完这一篇，你能回答」的 5 个问题一一对应，可检验。

## 三、与源码不符的地方

- `L426`（同一表述也出现在 `L116`）文档说：「上层只认一种结构：`ToolCallRequest(id, name, arguments)`。」；**源码实际：`ToolCallRequest` 有四个字段，第四个是 `provider_specific_fields`**。证据：`src/llm/base.py:44`–`47`（`id: str | None` / `name: str` / `arguments: Any` / `provider_specific_fields: JsonObject = field(default_factory=dict)`）。建议改成：「上层只认一种结构：`ToolCallRequest`。它只用到 `id`、`name`、`arguments` 三个字段，另有一个 `provider_specific_fields` 存原始供应商字段。」
- `L369` 文档说：「三个来源一起查。源码里是 arXiv 和 OpenAlex。第三家是 Semantic Scholar。」；**源码实际：三个来源在同一次初始化里一起注册，不存在「前两家在源码里、第三家另算」的分法**。证据：`src/paper_retrieval/service.py:423`–`437`，`_build_default_connectors` 一次返回 `{"openalex": ..., "semantic_scholar": ..., "semantic": semantic, "arxiv": arxiv}`（`semantic` 只是 `semantic_scholar` 的别名，`_select_connectors` 按对象身份去重，见 `service.py:467`–`470`）。建议改成：「默认注册三家来源：arXiv、OpenAlex、Semantic Scholar。三家一起并发查。」
- `L227` 文档说：「`get_history` 的 `turns` 取 1 到 10，默认 3。」；**源码实际：工具的 JSON schema 只声明了「默认 3，最大 10」，下限 1 来自 handler 里的硬编码截断**。证据：schema 见 `src/agents/research/tools.py:467`–`470`（描述原文「默认 3，最大 10」），下限见 `tools.py:1770`（`cleaned_turns = max(1, min(cleaned_turns, 10))`）。文档的结论没错，只建议补一句来源：「`turns` 默认 3，上限 10；下限由代码截到 1。」
