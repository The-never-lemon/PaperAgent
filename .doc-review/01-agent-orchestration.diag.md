# doc/arch/01-agent-orchestration.md 诊断

## 一句话总评

骨架和讲法（全局图、决策-取舍、代码事实核对）在整套文档里是最扎实的一篇，但「设计理念」12 条决策被整段前置到正文之前，新人在还不知道主循环、子 Agent、综述长什么样的时候就要连读 12 条取舍，读不下去；同时正文里有 1 处代码事实写错（小节内的进度回调并不是用 `ContextVar` 传的），1 处用词撞上简历红线（「用量……累加」）。

---

## 一、必须保留的东西

改写时一条都不许丢：

- **§0 的 mermaid 全局图**（`L21`–`L37`）。一张图把「入口 → 后台任务 → 两条路 → 主循环 → 工具 → 三个子 Agent → 检查点 → SSE → 前端卡片」串完，是本篇最有价值的东西。
- **§0 的导读法**：「从左上角看起」+「工具表里一共 11 个工具。这 11 个里有 3 个背后是子 Agent」（`L39`、`L45`）+「往后每一节，大致对应图上的一个方框」（`L53`）。这套讲法让读者始终知道自己站在图的哪个格子。
- **§1.1 的「先落库、再执行」**（`L300`–`L304`）。全篇少数几个把「为什么」而不是「是什么」讲透的地方：进程崩溃不丢消息、下一轮可以从消息表重建历史、当前消息不必层层传参。三句话，三个好处，都要留。
- **§2.2 的 contextvars 取景**（`L387`–`L405`）。用「每个任务各拿一份副本，函数的参数表一个字都不用改」解释 task-local，比抽象讲 ContextVar 好得多。
- **§2.3 的四道过滤**（`L427`–`L435`）。按 1/2/3/4 编号列出，每条都给反例（`[a+b]`、`[^1]`、`[论文一]`、`[TODO]`、`[1]`）。这种「规则 + 反例」的写法要保留，而且 §7 的事件树规则可以照它改写。
- **§6 的 mermaid 综述图 + 图例**（`L618`–`L644`），特别是「`write_section` 上面那个自指的箭头，含义是「还有小节就继续写」」这一句。图不解释等于没画，这句要留。
- **§6 的 `NodeCancelledError` 那一段**（`L665`–`L669`）。把「LangGraph 把取消异常换成普通 Exception，代码必须转回来」这个坑写出来了，新人踩不到，这是真价值。
- **决策 10 的整段**（`L219`–`L237`）。卡片标题、`notice`、不进长期记忆三条一起讲，最后落到「这关系到产品的诚实性」。这是全篇最有人味的段落。
- **决策 12 的实测依据**（`L267`）：「一篇真实论文的 37 个片段里，有 4 个是孤立页码。这约 11% 的模型调用没有产出。」给数字比讲道理有说服力。
- **§7 的 5 条卡片规则**（`L711`–`L719`）。短、并列、每条一个机制，是这个文档里最像「规范」的一段。
- **小结 5 条**（`L755`–`L762`）。可执行、可检验，末尾不要动。

## 五、对新人上手不友好的地方

1. **术语零解释就开讲**。`L47` 之后马上就是「工具卡」「工作区」「档位」「检查点」，但这些词在本篇里没有定义。README 有一张术语表（`doc/arch/README.md:22` 起），可新人是从本篇点进来的。建议在 `L15` 之前加 6–8 行最小术语表，或至少在首次出现处各加一句短解释。
2. **「设计理念」整节挡在正文前面**。`L55`–`L267` 是 12 条决策，读完一百多行才见到 §1。而决策 9（插图成批）、11（`chunkId` 换 `paperId`）、12（表格公式整块）讲的是精读与切分片的细节，读者要到 §4.1 和 §6.1 才能看懂。`L189`「决策 8」用到的「节点 id / 步骤 id」更是在 §7 才定义。
3. **`L53` 的「你现在站在第 1 节的位置」与实际章节号矛盾**（见第三节）。新人对不上号会反复回翻。
4. **§4 的编号步骤把「降级」排在了 reduce 之后**（`L521` 第 7 条）。源码里下载失败是直接跳到摘要精读、根本不会进 map 和 reduce（`deep_read.py:318`–`L331`）。照文档的顺序读，会以为先 reduce 再降级。建议把第 7 条挪到第 4 条后面，或改成「4a. 下载或转换失败 → 直接跳到第 7 步的降级路径」。
5. **§3 末尾混进考古信息**（`L497`–`L507`）：「`BaseAgent` / `AgentSpec` 现在只留给摘要阅读用」「旧的 `ReviewRequest`、`AgentRunInput` 这一类契约已经删掉」。新人无法判断这些是「已废弃、不用管」还是「还要用」。建议压缩成一句，或整段移到附录。
6. **§2.2 假设读者懂 asyncio**。「`asyncio` 的任务之间天然隔离 context」「控制权交还给事件循环」「让出一次」（`L95`、`L415`、`L417`）——全篇没有一处解释协程和事件循环是什么。至少要给「让出＝把执行权先交给推流协程，让页面先刷新」这样一句人话（`L415` 有半句，建议提前到首次出现处）。
7. **§6 的 `_bind_node` 那三句读三遍仍不懂**（`L647`–`L651`）：「LangGraph 靠函数签名判断返回值」「返回值要么是状态更新，要么是没执行完的协程」「代码会误判 lambda」。建议改成：「LangGraph 判断返回值时，先看这个函数是不是 `async def`。是，就当协程等它跑完；不是，就当状态更新直接用。lambda 看不出是不是 `async def`，所以协程对象会被当成状态更新，直接报 `Expected dict, got coroutine`。」
8. **§7 的五条规则缺少铺垫**。`L713` 直接给出 `{turn_id}:chat` 和 `{turn_id}:tool:deep_read_paper_r1_0`，但「节点」和「步骤」在本篇前面从未定义过这两个层级。建议在 §7 开头补两句：「一次工具调用会发一串事件。最外层是节点事件，节点下面挂步骤事件。」
9. **§3 的 ASCII 图与紧随其后的三个入口函数没有对齐**（`L468`–`L485`）。图里写的是「`deep_read_paper` → `run_deep_read`」，紧接着的列表却直接列 `run_deep_read` / `run_paper_qa` / `run_review`。新人有很大概率以为工具就叫 `run_deep_read`。建议把这段改成一张两列表：「工具名 | 入口函数」。

## 六、结构建议

现在的顺序是：【§0 全局图】→【设计理念 12 条】→【§1 请求接入】→【§2 主 Agent】→【§3 分层】→【§4 精读】→【§5 追问】→【§6 综述】→【§7 事件树】→【§8 技能文档】→【小结】。对「从没接触过项目的人」不友好，具体调整如下。

1. **把「设计理念」整节移到「小结」之前，改编号为 §9「设计理念：为什么是这个形状」**。理由：12 条决策全部依赖正文的术语（主循环、子 Agent、检查点、工具卡、片段）。读者先看机制、再看取舍，决策才是「恍然大悟」；反过来读，决策只是 12 段听不懂的话。改后每节末尾保留「来龙去脉见 §9 决策 N」的指路，读者按需回跳。
2. **若不愿大动，折中方案**：决策 1–8 留在前面（讲的是编排骨架，勉强能读），把**决策 9、11、12 移到对应章节旁边**——决策 9（插图成批）移到 §4.1，决策 11（`chunkId` 换 `paperId`）移到 §6.1，决策 12（表格公式整块）移到 §4.1 的装箱规则之后。这三条讲的是局部细节，跟着细节走才好懂。
3. **§3「Agent 分层」上移到 §2 之前**，成为新的 §2，原 §2 顺延为 §3。理由：先给「一个主 Agent + 三个子 Agent」的角色分工，再讲主 Agent 怎么跑，读者看 §2（原）时才知道那些工具背后是谁。
4. **§0 与 §1 合并**。`L15`–`L53` 的全局图与 `## 1. 请求怎么接到主 Agent` 讲的是同一件事的两层（先看整体、再看第一步），中间被「设计理念」隔开了。合并后编号从「1. 全局图」开始，`L53` 的「你现在站在第 1 节」也自然对上了。
5. **补一节「动手改一处」**，放在 §8 之后。现成素材：`L727`「新增工具时要在这里补一条」+`L486`–`L493` 的三条约定 + `L733` 的技能文档加载器。合成一份三步清单：「加一个工具要走哪几个文件」「改一句提示词要动哪个文件」。这是新人最需要、也是本篇最缺的东西。
6. **§8「技能文档」与编排主题关联很弱**，通篇只有「提示词怎么加载」这一件事和编排沾边。建议并入 §3（Agent 分层）末尾，或独立成一小篇，不要占一个三级节号。
7. **每节末尾统一加一行「源码从这里开始看」**。现在只有 `L275`、`L289`、`L360`、`L395`、`L636` 等少数几处给了文件入口，其余章节要读者自己找。格式建议：`> 源码：src/agents/reading/paper_qa.py 的 run_paper_qa 与 _handle_read_sections`。
8. **`L5` 的「读完这一篇，你能回答」5 个问题保留**，但建议每题后面补一个括号，指向对应小节（例如「……为什么不统一成一种？（§4–§6）」）。现在读者要读完全篇才能回去认领这 5 个答案。
